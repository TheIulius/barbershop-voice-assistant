# ტელეფონის ხაზის მიერთება (ნაბიჯ-ნაბიჯ)

## როგორ მუშაობს (მოკლედ)

```
კლიენტი რეკავს ბარბერის ჩვეულებრივ ნომერზე
   │  ბარბერი არ პასუხობს / დაკავებულია  →  ოპერატორი ზარს გადაამისამართებს (call forwarding)
   ▼
ტელეფონის პროვაიდერის ნომერი (Twilio)         ← ეს ნომერი ჩვენ ვიყიდეთ/ავიღეთ
   │  პროვაიდერი ჩვენს სერვერს ეკითხება: „რა ვუყო ზარს?“
   ▼
ჩვენი სერვერი (Render)  ⇄  Gemini (ხმოვანი AI)  →  ჯავშანი ეწერება
```

პროვაიდერი ზარს იღებს, ხმას ინტერნეტით გადასცემს ჩვენს სერვერს, სერვერი – Gemini-ს, პასუხი იმავე გზით ბრუნდება.
ბარბერს **თავისი ნომერი რჩება** – ის უბრალოდ ოპერატორთან ჩართავს გადამისამართებას.

## რა გჭირდება შენგან

1. **Twilio-ს ანგარიში** (twilio.com). რეგისტრაცია ითხოვს ელფოსტას და ტელეფონის დადასტურებას SMS-ით. ტესტისთვის საკმარისია უფასო „trial“
   (დაახლ. $15 საცდელი ბალანსი, ბარათი არ სჭირდება). რეალური მუშაობისთვის დასჭირდება ბარათი და ზრდასრული პირი ანგარიშზე.
2. **ნომერი Twilio-ში**: Console → Phone Numbers → Buy a number. [არ არის დადასტურებული, აქვს თუ არა Twilio-ს საქართველოს ნომრები; პირველი ტესტისთვის აიღე ამერიკული ან ბრიტანული ნომერი, ხმოვანი ზარის მხარდაჭერით.]
3. **Render-ზე ორი რამ** (ამას შენ ჩაწერ, საიდუმლოს მე არ ვითხოვ):
   - Environment → **TWILIO_AUTH_TOKEN** = Twilio Console-ის მთავარ გვერდზე „Auth Token“ (Show ღილაკი).
   - Environment → **TELEPHONY_ALLOWED_TO** = შენი Twilio ნომერი ფორმატით `+1XXXXXXXXXX` (სურვილისამებრ, მაგრამ რეკომენდებულია).
   - `PUBLIC_BASE_URL` უკვე ჩაწერილია render.yaml-ში (`https://barbershop-voice-assistant.onrender.com`).
4. **Twilio-ში ნომრის გვერდზე** → Voice Configuration → „A call comes in“ = **Webhook**, URL:
   `https://barbershop-voice-assistant.onrender.com/telephony/voice`, მეთოდი **HTTP POST**. Save.

## პირველი ტესტი (უფასო, ბარბერის გარეშე)

დარეკე შენი მობილურიდან Twilio-ს ნომერზე. მთელი ჯაჭვი ტელეფონის გარეშეც გატესტილია (იმიტირებული Twilio, `scripts/phone_sim.py`),
ამიტომ პირველივე ზარზე უნდა გაიგო მისალმება. თუ არა: Render → Logs-ში ეძებე `[phone]` ხაზები:
- `webhook refused: bad signature` → Twilio-ში URL არ ემთხვევა `PUBLIC_BASE_URL`-ს, ან Auth Token არასწორია.
- `stream refused` → ზარს 2 წუთზე მეტი გაუვიდა webhook-სა და ხმას შორის (სერვერი ეძინა).

## ბარბერის ნომრის მიერთება (გადამისამართება)

GSM სტანდარტული კოდები ბარბერის ტელეფონზე (მისი ნომრიდან აკრიფოს და დარეკოს):

| რა | კოდი |
|---|---|
| თუ არ პასუხობს (20 წამი) | `**61*+1XXXXXXXXXX**20#` |
| თუ დაკავებულია | `**67*+1XXXXXXXXXX#` |
| თუ გამორთულია / არ არის ქსელში | `**62*+1XXXXXXXXXX#` |
| ყველაფრის გაუქმება | `##002#` |

[გადაუმოწმებელია] აქვს თუ არა საქართველოს ოპერატორს (Magti, Silknet, Beeline) შეზღუდვა უცხოეთის ნომერზე გადამისამართებაზე და რა ღირს წუთი
(ეს ფასს **ბარბერი** იხდის გადამისამართებულ ზარზე). ეს ერთ ზარში გადამოწმდება: ოპერატორის ცენტრს დაურეკეთ და ჰკითხეთ.
თუ ძვირია, ალტერნატივაა ქართული ნომრის აღება პროვაიდერისგან (მაგ. Telnyx ან Zadarma) და ბარბერის მომხმარებლებისთვის ამ ახალი ნომრის გაცემა.

## სანამ რეალურ კლიენტებს მისცემ – აუცილებელი ხარვეზები

1. **ჯავშნები ახლა სერვერის დროებით დისკზე ინახება** და Render-ის თითოეულ გადატვირთვაზე იკარგება. რეალური მუშაობისთვის უნდა მიერთდეს Google Calendar (კოდი არსებობს, რეალურ კალენდარზე არ გაგვიტესტავს).
2. **Render უფასო სერვერი 15 წუთის უმოქმედობის შემდეგ იძინებს** და გაღვიძებას ~1 წუთი სჭირდება – პირველი ზარი ვერ აიღებს. გამოსავალი: უფასო „ping“ სერვისი ყოველ 5 წუთში `/healthz`-ს აკითხავს, ან Render-ის ფასიანი გეგმა (~$7/თვე).
3. **ზარის ბიუჯეტი**: `DAILY_CALL_MINUTES=90` რეალურ ზარებსაც ზღუდავს. რეალური გამოყენებისას გაზარდე Render-ის Environment-ში.
4. **ხმის ხარისხი ტელეფონზე უარესია** (8 kHz), ამიტომ სახელებისა და ნომრების გაგება ბრაუზერზე ცოტა უარესი იქნება; ამიტომ ნომერს ყოველთვის კითხულობს უკან და ადასტურებს.
5. **კანონი/კონფიდენციალობა**: კლიენტებს უნდა ეთქვათ, რომ ზარს AI პასუხობს (მისალმებაში), და სად ინახება მონაცემები. ზარების ჩანაწერებს (აუდიოს) სისტემა არ ინახავს, მხოლოდ ტექსტურ ლოგს.
